# Phase 5: Feedback, Recovery, and Canonical Discomfort History

## Eligibility and immutable submission

One `SessionFeedback` may be submitted for an owned `COMPLETED` or `PARTIAL` `WorkoutSession` until **24 hours after `finishedAt`**. Submission is optional and never blocks workout finalization. Students can defer it and resume from their workout history during that window. `NOT_STARTED`, `IN_PROGRESS`, `CANCELLED`, and `SKIPPED` are ineligible. A student submits **once**; no student edit endpoint exists. Exact request retries return the stored feedback; a different payload after submission conflicts. Trainer/support corrections, if ever needed, require a separately designed audited revision workflow, not mutation of this record.

The feedback record stores organization, student, session, UTC submission timestamp, numeric session RPE (1–10), perceived state, recovery state, optional general notes, and whether discomfort was reported. Session RPE is the student's subjective effort **during this workout**. Perceived state (`VERY_GOOD`, `GOOD`, `NORMAL`, `DIFFICULT`, `VERY_DIFFICULT`) is how the workout felt overall. Recovery state (`VERY_RECOVERED`, `RECOVERED`, `NORMAL`, `TIRED`, `VERY_TIRED`) is how recovered the student felt **on arriving**. These complementary self-reports are not a diagnostic score or a formula inferred from completed sets.

## Discomfort and early-finish merge

`SessionSafetyEvent` remains the **canonical incident** record across phases. Phase 4 already creates an immutable `EARLY_FINISH` event for `DISCOMFORT_OR_PAIN` or `FEELING_UNWELL`. Phase 5 adds one relational `DiscomfortReport` per reported body region on feedback, with intensity 1–10, optional session exercise/canonical exercise reference and note. Each discomfort report points to exactly one safety event of the same session and organization. If an early discomfort event exists, the matching report **reuses its ID**; when the early event lacked a region the first report supplies detail through that relation. Additional locations, or discomfort first mentioned on a completed workout, create `SESSION_FEEDBACK` safety events linked to that feedback in the same transaction. A Phase 4 feeling-unwell event is retained as its own fact; it does not force a discomfort report.

When an early discomfort event exists, submitted feedback cannot say “no discomfort.” If the early event already recorded a location, the feedback must include that location. Early severity and later reported intensity may differ; the early event remains immutable and the report records the later student detail. Reports are unique by feedback and body region, so a retry cannot create duplicate locations. `OTHER` may carry a short optional location description. An optional `exerciseId` must be an organization-owned canonical exercise present in this exact session's `SessionExercise` snapshots; no exercise is assumed to be the cause.

Future recurrence counts use canonical safety events, **one distinct workout session per body region** in a stated window. When an event has a linked report, use the report's effective region/intensity; otherwise use the early event's known region/intensity. Never count the early event and its feedback detail as two incidents. A report with no early event still has its own canonical `SESSION_FEEDBACK` event. No medical-risk score, causal inference, diagnosis, or AI interpretation is performed in Phase 5.

## Authorization and privacy

The student may read/submit feedback only for their own eligible session. Active assigned trainers and organization admins may read their students' locked feedback and a small deterministic recent-signal summary; no trainer write endpoint exists. Composite tenant/session foreign keys, validated ownership, relational exercise-in-session checks, append-only triggers, range checks, and one feedback per session protect historical facts. Optional text is length-limited, rendered as text, excluded from normal logs and analytics dimensions, and is not sent to an AI provider in this phase.

The student UI asks effort, overall feeling, recovery, and a yes/no discomfort question. Only “yes” reveals one or more location/intensity rows with optional exercise and note. Early discomfort preselects “yes”; the completion screen links to the optional form, while history offers a later link only before expiry. Trainer views show the same factual reports without diagnosis. A development-only seed adds one small completed example with one discomfort report; running it repeatedly must not duplicate history or appear as a production default.
